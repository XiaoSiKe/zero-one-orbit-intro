## 新版 DSH Desktop 接入原理

本机桌面端为 0.2.1-rc.3。系统内置 CLI 在 `/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh`，可以直接执行 `plugin --profile desktop add <本地 tgz>`，无需全局安装第二套 DSH。

安装会把依赖登记到 `~/.dsh/profiles/desktop/package.json`，并将插件 bundle 加入 `dsh.profile.bundles`。插件随 Host 进程启动，提供 CSS、JS、音频和配置路由。

当前新版桌面壳直接加载打包 HTML，再通过 boot IPC 接收 `webServer.collectIndexInjections()` 收集的启动注入表。插件监听官方 `webserver/index-inject` 事件，顺序提供内联样式、启动配置、首屏根节点、启动判定脚本和动画运行时。旧载体仍走 `tapIndex()`；同一载体只选择一条路径。

动画是覆盖在主界面上的 DOM/SVG 层，由 CSS 与 JavaScript 推进。DSH 主界面可以在背后同时加载。完成、跳过或异常兜底时，动画移除覆盖层、释放滚动和交互，并发出完成事件。授权和身份确认按钮仅用于推进动画，不改变 DSH 的真实工具权限。

播放配置为 `~/.dsh/dsh-startup.json`。`enabled` 控制开关，`mode: always` 表示每次界面加载播放，`requireInteraction` 决定前两步是否等待点击。音频与图形全部本地运行，不调用模型生成动画。

2026-10-27 接入状态：已通过官方 CLI 登记旧插件；新版桌面注入兼容已完成并增加 8 项回归检查。本机另有 `dsh-rixin-startup` 原生开场。机械环轨版的接入按用户要求暂停，播放开关关闭；新版适配包尚未升级并完成桌面实机验收。需要用户明确要求继续后再处理接入。未修改签名应用安装包，也未覆盖另一工程。

## 流畅度与机械音效优化（2026-10-27）

- Logo 改为经同源本地资源路由读取，保留原始 JPG；运行时 CSS 从约 526KB 降至约 55KB，避免大段 data URI 的样式解析和重复图片解码。
- 扫描、进度、阶段条与声纹用 transform 驱动；十六进制读数改为纯文本更新。
- 结束／跳过时停止并断开声音节点、关闭 AudioContext、清理全局输入监听器与 DOM 观察器；重播先释放旧实例，防止旧完成事件干扰新播放。
- 电机、伺服、继电器、气动和低频锁扣叠加为机械声层；噪声缓冲复用、素材请求去重，机器声经过峰值控制，旁白播放时降低机器声。浏览器未解锁声音前不积压开场音效。

本机 IAB、4× CPU 压力、关闭声轨以固定阶段时长的两次对照：最长帧从约 83–85ms 降为约 18–34ms；50ms 以上长任务从每次 2 项降为 0；布局计算从约 542 次降为约 356 次。该结果针对本地视觉预览，不代表其他设备或真实宿主并行任务的固定帧率。

欢迎幕计时回归覆盖 0.5×、1×、3×：文字与故障切片结束后清晰停留至少 3.2 秒。浏览器复测可追加 `?speed=3`，结果包含 `welcomeReadingMs`。

可复测页面：`/test/performance.html`；机械声音离线试听：`/test/sound-preview.html`。音频缓存、停止与静音检查在 `test/smoke-audio.mjs`。本次不安装、启用或切换 DSH 桌面插件，接入仍暂停。
